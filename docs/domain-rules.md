# JIG Data Finder 领域模型与数据规则

> 依据车间现场说明整理（2026-10-23）。本文是**业务事实的唯一来源** ——
> 代码、测试数据、界面文案与它冲突时，以本文为准。

---

## 一、术语

| 术语 | 含义 | 备注 |
|---|---|---|
| **P/N** | 料号，信息层级的最高级 | Lot / CST 的父级 |
| **JIG** | 一张 2.2 m × 2.5 m 的金属制板材 | **只作名词，不翻译为"夹具"** |
| **CST** | cassette 缩写，装载 JIG 的载体，共 20 层 | 现场共 40 个：`D8CCST500001` – `D8CCST500040` |
| **Lot ID** | 系统为管理 JIG 而创造的概念，是 JIG ID 的集合 | 与 CST 绑定 |
| **工程** | 该 LOT / CST 当前的工序 | 每个 LOT / CST 唯一 |
| **Slot** | CST 的层号，1 – 20 | 一层装一块 JIG |

**用词约定**：JIG 只作名词使用，不译为"夹具"。2026-10-23 已把代码注释、
界面文案与文档里遗留的中文译名统一为 JIG。

---

## 二、信息层级

```
P/N                                  最高级，Lot / CST 的父级
 │
 ├─ Lot ID  ┐
 ├─ CST ID  ├─ 同级
 └─ 工程名  ┘
      │
      └─ Slot No   (1 – 20 层)
           │
           └─ Jig ID                一张金属板
```

- **Lot ID / CST ID / 工程名 三者同级**，都挂在 P/N 之下、Slot 之上。
- **型号**与**由型号派生的「对应尺寸」**不在这个层级里 —— 它们是 **JIG 的属性**。
  判定结论同样属于 JIG 的属性，随 JIG 走。

---

## 三、实体关系与约束

| 关系 | 基数 | 说明 |
|---|---|---|
| P/N → Lot | 1 : N | P/N 是 LOT 的父级 |
| Lot ↔ CST | 1 : 1 | LOT 是信息侧的管理单元，CST 是实物侧的载体，一一对应 |
| Lot → JIG | 1 : N | 一个 LOT 就是一组 JIG ID |
| CST → Slot | 固定 20 | 层号 1 – 20 |
| Slot → JIG | 1 : 1 | **一层一块 JIG，(CST, Slot) 全局唯一** |
| Lot/CST → 工程 | 1 : 1 | 任一时刻只处于一道工序 |

**产线容量**：40 个 CST × 20 层 = **800 个 JIG 位**。
一份导出里的记录数不会超过这个上限；超出即说明数据有问题。

### 空值规则（重要）

**LOT 不能为空，CST 可以为空。**

- LOT 是信息合集，没有 LOT 的行没有意义，任何工程下都必须有值。
- CST 只是实物载体。LOT 在 **JIG Loading** 阶段尚未上载，可以脱离 CST
  单独存在（此时 CST 列为空，LOT 照常有值）。
- **这条豁免只对 JIG Loading 成立**：其他工程里 JIG 已经装在某个具体的
  CST / 层位上，CST 必须存在，否则"这块板现在在哪一层"无从回答。

读取侧的处理：`pivot.ts` 在 CST 为空时**用 Lot ID 回填**，所以透视表里
脱离载体的 LOT 会以 Lot ID 出现在「CST ID」列，仍能参与分组与计数。

## 四、P/N 编码规则

格式：`<前缀>-<4 位尺寸码><1 位字母后缀>`，三段都取自白名单，
且**尺寸码决定了前缀与可用后缀**（不是自由组合）。

| 尺寸码 | 前缀 | 可用后缀 | 对应尺寸 | 合法组合数 |
|---|---|---|---|---|
| `6555` | `6073J` | B C D E F G H | 65/55 | 7 |
| `7748` | `6072J` | B C D E F G | 77/48 | 6 |
| `8348` | `6072J` | B C F G | 83/48 | 4 |
| `7727` | `6073J` | C | 77/27 | 1 |
| `3931` | `6073J` | C | 39/31 | 1 |
| `7742` | `6072J` | B C | 77/42 | 2 |

合计 **21 个合法 P/N**。

三条硬约束：

1. **前缀与尺寸码绑定**：`6555` 只出现在 `6073J` 下，`7748` 只在 `6072J` 下。
   两者互换即为非法编码。
2. **后缀集合逐码不同**：`K` 不在任何尺寸码的合法后缀里。
3. **尺寸码的位置固定**：P/N 第 7 – 10 位（`pnExtractStart=6`, `pnExtractLength=4`），
   判定取的就是这 4 位。

**实际生产分布**（现场观察，非硬规则）：尾缀通常不超过 2 类，尺寸不超过 4 类。

## 五、判定规则

- 「对应尺寸」由 **JIG 的型号**查映射表得来（`config.jigSizeMapping`），
  是 JIG 的属性，不是 P/N 的属性。同一型号的所有 JIG 共享同一套尺寸串。
- **标红条件**：P/N 的尺寸码（第 7 – 10 位）必须**精确等于**「对应尺寸」里
  某个 4 位规格码；`All Size` 恒匹配、空值视为匹配。
- 例外对象（"型号能做、但这台做不到"）已于 2026-10-23 随业务变化下线，
  现在标红只剩上面这一条规则。

| 项 | 现状 | 规则 |
|---|---|---|

| CST 编号 | `D8CCST500001` – `D8CCST500025`（其中 2 个 LOT 不占 CST） | 在 `500001` – `500040` 内 ✅ |
| Lot | 25 个 | ✅ 无一为空 |
| Lot ↔ CST | 23 个已绑定，一对一；2 个在 Jig Loading 脱离 CST | ✅ 空 CST 只出现在 Jig Loading |
| (CST, Slot) | 按回填后的载体计无重复，每载体 slot 恰好 1–20 | 一层一块 ✅ |
| P/N | 21 个，全部满足"码决定前缀与后缀" | ✅ 违规 0 行 |
| 每个载体的 P/N / 工程 | 各自唯一 | ✅ |

## 八、后续可选项

1. **透视表行数预期**：按真实装载，(P/N, CST) 组合最多 40 个，透视表行数 =
   P/N 小计行 + 组合数 + 1 总计行。当前 500 行数据是 21 + 25 + 1 = **47 行**
   （改造前是 127 行）。若要让透视再"厚"一些，只能增加数据量或让一个 CST
   服务多道工序 —— 后者违反规则，不做。
2. **`pivot.ts` 可加断言**：把"每个 (P/N, CST) 只能有一道工序"挡在生成阶段
   而不是靠人工核对。目前由 `test-500.test.ts` 覆盖，运行时暂不校验。
3. **`tests/fixtures/jig-exceptions.json` 文件名**已名不副实（例外功能已下线，
   现在只存分组意图）。改名会牵动生成脚本与测试两处，暂未动。
