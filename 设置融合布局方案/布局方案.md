# 「型号尺寸匹配」融合进「设置」——布局方案

> 配套界面稿：同目录 `index.html`（浏览器打开，可点左侧四个分类切换，深色「控制室」皮肤）

---

## 0. 结论先行

**推荐方案 A：把「设置」升级成一个"偏好设置窗口" —— 左侧分类导航 + 右侧内容面板 + 底部统一操作条。**

- 对话框宽 **880px**、高 **有界（min(640px, 100%)）**，左导航 200px 固定、右面板独立滚动；
- 四个分类：**文件 / 界面 / 数据处理 / 型号尺寸匹配**；
- 底部保留 **取消 / 保存设置**，两者合并为**一次写盘**；
- 映射表**不再内层滚动**，随右面板整体滚动、表头 sticky —— 消除"滚动区套滚动区"。

理由一句话：**映射表要宽、设置项要窄，只有分栏能让两者各得其所，且以后再加分类不用动结构。**

---

## 1. 现状：两个独立面板

| | 设置 | 型号尺寸匹配 |
|---|---|---|
| 入口 | 顶栏「设置」 | 顶栏「型号尺寸匹配」 |
| 外壳 | `.dialog`（min 660px） | `.dialog .dialog--wide`（min 820px） |
| 内容 | 3 个 `fieldset`：文件(2) / 界面(4) / 数据处理(3) | 一张 16 行的映射表 |
| 滚动 | `.dialog__body` 整体滚动 | 列表**内层**滚动（`max-height: min(46vh,420px)`） |
| 草稿 | `d: SettingsDraft` | `pairs: MappingPair[]` |
| 校验 | 无 | `validateMappingPairs` → 有错**禁用保存** |
| 特殊行为 | 主题**即时预览**，关闭时还原 | 重复/空型号报错、首错自动滚入、拖拽排序、恢复默认 |
| 保存 | `saveSettings` → 写盘 | `saveSizeMapping` → 写盘（只 patch 两个字段） |
| 关闭 | ESC / 取消 / **点遮罩不关** | 同左 |

> 现面板头部注释写明「独立于设置」的两个理由：①660px 放不下表格；②这是最常用也最易错的一块，值得单独入口。
> 融合方案必须**正面回应这两点**，否则就是退步。

---

## 2. 融合要解决的 5 个真问题

1. **宽度冲突**：表格要 ~820px，设置列 660px 就很舒服 —— 不能只挑一个宽度将就。
2. **双层滚动**：设置 body 会滚，映射列表自己也滚；融合后若原样堆叠，会出现「滚动条里套滚动条」，鼠标滚轮归属混乱。
3. **校验耦合**：映射有错时，**要不要连主题、行高这些无关改动一起不许保存？**
4. **两套草稿 + 主题预览**：设置是草稿式、主题是即时预览需还原；映射也有自己的 draft。合并后要保证「切分类不丢草稿」「关闭能正确还原」。
5. **入口不能变难找**：映射是高频操作，融合后不该被埋在长表单末尾。

## 3. 三个备选方案

| | A 左导航 + 右内容（**推荐**） | B 单列加一个分组 | C 对话框内横向 Tab |
|---|---|---|---|
| 结构 | 左 200px 导航 + 右面板 | 一根长表单，末尾接映射表 | 顶部 Tab 切四类 |
| 映射表宽度 | 右面板全宽，充裕 | 对话框得整体加宽到 820 | 同样充裕 |
| 滚动 | **单一滚动轴**（右面板） | 双层滚动（body + 内层列表） | 单一滚动轴 |
| 找映射 | 一次点击，且带计数徽章 | 要滚到最底 | 一次点击 |
| 与主界面 Tab 混淆 | 无（导航在左，语义不同） | 无 | **有**（模态里再来一条 Tab 栏） |
| 扩展性 | 加第 5 类只加一行 | 越加越长 | Tab 会变挤 |
| 改动量 | 中 | **小** | 中 |
| 视觉风险 | 低（复用现有令牌/类） | 低 | 中（两条 Tab 栏打架） |

**结论：A。** C 被否掉的唯一理由就是"模态里再放一条 Tab 栏"与本应用顶部的四条主视图 Tab 语义撞车。

## 4. 方案 A · 详细布局

### 4.1 结构图

```
┌──────────────────────────────────────────────────────────────┐
│  设置                                          （标题 + 一行说明）│  head 56px
├───────────────┬──────────────────────────────────────────────┤
│ ▏文件          │                                              │
│   界面         │   当前分类的内容面板                          │
│   数据处理     │   （唯一滚动区）                              │
│   型号尺寸匹配 │                                              │
│        · 16 条 │                                              │
│               │                                              │
│  nav 200px     │   pane 自适应                                 │
├───────────────┴──────────────────────────────────────────────┤
│                                    [ 取消 ]  [ 保存设置 ]      │  foot 56px
└──────────────────────────────────────────────────────────────┘
        width: min(880px, 100%)   height: min(640px, 100%)
```

### 4.2 尺寸与栅格

| 部位 | 规格 |
|---|---|
| 对话框 | `width: min(880px, 100%)`；`height: min(640px, 100%)`；圆角 10px（沿用皮肤） |
| 网格 | `grid-template-rows: auto 1fr auto`（头 / 主体 / 脚） |
| 主体 | `grid-template-columns: 200px 1fr`；`min-height: 0` |
| 头部 | 高 56px，内边距 `0 22px`；标题 15px/650 + 说明 12px 弱化 |
| 左导航 | 200px，内边距 `10px 10px`，项高 34px |
| 右面板 | 内边距 `20px 22px`；`overflow: auto` |
| 脚部 | 高 56px，`justify-content: flex-end`，间距 8px |
| 分隔 | 只用 **1px 结构线**（`--rule-strong`），不用卡片投影 |

### 4.3 左导航（`.prefs-nav`）

- 四项，纯文字（不加图标，保持"设备状态板"的克制）：

  ```
  文件
  界面
  数据处理
  型号尺寸匹配    · 16 条
  ```

- **选中态**：左侧 2px 青绿光条 + 淡底（`--accent-soft`）+ 文字加粗 —— 沿用工序轨道节点竖规的视觉语言，全应用统一。
- **计数徽章**：只给「型号尺寸匹配」，显示当前规则条数；**有校验错误时转红**（复用 `.map__count[data-bad]` 的语义色）。
- **键盘**：`↑ / ↓` 在项间移动，`Enter / Space` 切入；Tab 顺序 = 导航 → 右面板 → 脚部按钮。
- **角色语义**：`role="tablist"` / `role="tab"` / `aria-selected`，右面板 `role="tabpanel"` —— 与主界面 Tab 用同一套无障碍模型。

### 4.4 右面板内容

**① 文件 / ② 界面 / ③ 数据处理**：把现有三个 `fieldset` **原样搬进来**（`.fieldset` / `.field` 一行不差），只是外面多了左导航。视觉零变化，回归风险最低。

**④ 型号尺寸匹配**：

```
说明：型号 → 对应尺寸；尺寸串用 _ 分隔互斥组，如 65/55_77/48
────────────────────────────────────────────────────
[ 新增 ]  [ 恢复默认 ]                    16 条规则
┌──┬──────────┬────────────────────┬─────┬──────┐
│⠿ │ 型号      │ 对应尺寸            │ 顺序 │      │  ← 表头 sticky
├──┼──────────┼────────────────────┼─────┼──────┤
│⠿ │ 184      │ 65/55              │ ↑↓  │ 删除 │
│⠿ │ 430      │ 65/55_77/48_83/48  │ ↑↓  │ 删除 │
│⠿ │ 430      │ 65/55_77/48_83/48  │ ↑↓  │ 删除 │  ← 行内红字：型号重复
└──┴──────────┴────────────────────┴─────┴──────┘
```

- **行结构与逻辑完全沿用** `SizeMappingDialog`（`⠿` 拖拽 / 型号 / 对应尺寸 / ↑↓ / 删除 / 行内错误），不新造轮子。
- **去掉内层滚动**：`.map__body` 的 `max-height` 取消，改为**右面板整体滚动**；`.map__head` 改 `position: sticky; top: 0`（面板内吸顶）。
- 说明文字从"标题下"下沉到面板顶部一行，12px 弱化色。

### 4.5 底部操作条

- 左空、右对齐：`[ 取消 ] [ 保存设置 ]`（主按钮青绿实心）。
- **一次写盘**：设置草稿 + 映射草稿合并提交，写一次 `config.json`。
- **校验联动（关键决策）**：
  - 保存时若映射有错 → **不保存**，自动**切到「型号尺寸匹配」分类** + `scrollIntoView` 首个错误行 + 计数转红 + 一句提示（`存在重复或空型号, 修正后才能保存。`）。
  - 「恢复默认」只作用于映射分类，**不动**文件/界面/数据处理的草稿。

### 4.6 滚动策略（融合成败的关键）

| | 融合前 | 融合后 |
|---|---|---|
| 设置 body | 滚动 | 不滚动（面板内滚） |
| 映射列表 | 内层滚动 | **不滚动** |
| 右面板 | — | **唯一的滚动轴** |
| 表头 | 跟随 | **sticky 吸顶** |

> 只有一条滚动轴，滚轮行为确定、不打架。这是 A 相对 B 最实质的收益。

### 4.7 状态与交互细则

- **切分类不丢草稿**：四类内容同属一个对话框的 state，来回切不受影响（B 方案里映射表在页尾，滚来滚去反而更容易误操作）。
- **主题即时预览**保留：仍在「界面」分类里选，关闭时按 `onThemePreview(initial.theme)` 还原 —— 还原时机仍挂在"取消/ESC"上。
- **ESC 只关一次**：融合后**只保留一个** keydown 监听（现在两个组件各有一个，合并时必须去重）。
- **点遮罩不关闭**：规则不变（逐行录入的保护）。
- **首次打开定位**：从顶栏进入时，若上次停留在某分类，可记住（可选）；默认打开「界面」还是「文件」，建议默认 **文件**，与现状一致。

### 4.8 最小窗口与响应式

- 应用最小窗口 900×600（`tauri.conf.json`）。
- 880 宽在 900 窗口里两侧各留 10px → 够；高度用 `min(640px, 100%)` 自适应，600 高时对话框约 552（减去 `scrim` 的 24px 内边距）。
- 宽度不足的兜底：`@media (max-width: 800px)` 时把左导航压到 **160px**；若再窄（极端情况）可退化为顶部横向 Tab —— 属于可选增强，不影响主方案。

## 5. 方案 B（轻量备选）简述

若只想最小改动：**设置对话框整体加宽到 820px，末尾追加一个「型号尺寸匹配」`fieldset`，映射表保持内层滚动。**

- 优点：改动最小，几乎不动结构。
- 缺点：单页拉得很长；**双层滚动**（面板滚 + 列表滚）；四类内容挤在一根轴上，以后加分类只会更长。
- 适用：只想尽快合二为一、不在乎交互细节时。

## 6. 落地映射（改哪些文件）

| 文件 | 改动 |
|---|---|
| `src/ui/SizeMappingDialog.tsx` | 把**映射表主体**抽成 `SizeMappingSection`（复用全部逻辑：校验 / 拖拽 / ↑↓ / 恢复默认 / 首错滚动）；外层 `.scrim`/`.dialog` 外壳去掉 |

| `src/App.tsx` | 去掉 `showSizeMapping` 状态与顶栏「型号尺寸匹配」按钮；`saveSettings` 与 `saveSizeMapping` 合并成一个保存回调（一次 `writeConfigFile`） |
| `src/styles/app.css` | 新增 `.dialog--prefs` / `.prefs-nav` / `.prefs-nav__item` / `.prefs-pane`；`.map*` 全部沿用；`.map__body` 去内滚、`.map__head` 加 sticky |
| `src/styles/skin.css` | 左导航选中态的青绿光条与徽章配色（复用现有令牌，不引入新色） |
| `tests/` | 现有 185 项**不涉及 DOM**，预期不受影响；改完跑 `npm run verify` |

### 验收重点（都是融合特有的坑）

1. **滚动轴只有一条**（滚右面板，页面不再有第二根滚动条）。
2. **ESC 只关一次**（删掉重复的 keydown 监听）。
3. **主题预览能正确还原**（取消 / ESC / 保存三条路都验）。
4. **映射有错时**：保存被拦、自动跳到映射分类、滚到首个错误。
5. **切分类不丢草稿**；**取消**后磁盘配置零变化。

## 8. 需要你拍板的两点

1. **保存是否被映射校验阻塞**：推荐"阻塞 + 自动跳转"（避免写出半成品配置）；若你希望互不影响，可改成"映射有错时只跳过映射、其余照存"。
2. **默认打开哪个分类**：推荐**文件**（与现状一致）；也可以记上次停留的分类。
