# JIG Data Finder · 界面美化方案

> 概念代号：**「控制室」**（Control Room）
> 深色优先 · 单一磷光强调色 · 把车间看板升级成一台发光的检测仪器
>
> 配套高保真稿：同目录 `index.html`（浏览器直接打开，可切昼夜、可切标签页、有入场动效）

---

## 0. 一句话概念

现有界面是**一张写在白纸上的排产表**——工整、克制、信息密度高。
新方案把它变成**控制室里的检测台**：暗场、发光、精密，数据像仪器读数一样从黑底上浮起来。

不改信息架构（四条视图、工序轨道、透视下钻、审查标红全部保留），只把「纸」换成「屏」。

---

## 1. 先诊断：现有界面的四个"还可以更好"

| 现象 | 问题 | 机会 |
|---|---|---|
| 浅灰底 + 深绿强调色，整体**很平** | 缺乏视觉层次，表格与外围背景贴在一起，扫读时眼睛没有落点 | 用「暗场 + 局部发光」制造纵深，让数据自己成为光源 |
| 单一强调色（孔雀石绿）用在**所有**交互上 | 强调色通胀：按钮、选中、链接、计数格全是一个绿，等于没有强调 | 主张力色收敛到「检测灯青绿」一种，另设**琥珀（生产中）/ 红宝石（异常）**两个专用信号色，各司其职 |
| 工序轨道是**一排带色条的卡片** | 它是这个领域最独有的信息，却长得跟普通统计卡没区别 | 重做成一条**发光的产线流**——节点 + 流动光带，0 值节点自然沉下去，主力工序会呼吸 |
| 异常行只靠**红字** | 车间一眼扫过时，红字容易被忽略 | 异常升级为**左侧信号灯条 + 呼吸脉冲**，不依赖文字颜色也能定位 |

核心判断：**现有设计的"克制"是对的，缺的是"纵深"和"焦点"。** 新方案不是推翻它，而是给它加一个空间维度。

---

## 2. 美学方向（Mood）

> 深夜的检测工位。玻璃基板在暗场里被检验，检测灯投出一道青绿色的光；
> 墙上的排产看板还亮着，数字是等宽的，每一格都能纵向扫读。
> 空气里有极淡的胶片颗粒——不是脏，是"真实"。

三个关键词：**暗场（Dark field）· 磷光（Phosphor）· 精密（Precision）**。

这条方向之所以成立，是因为它**从业务里长出来**：JIG 是 2.2m × 2.5m 的金属检测板材，工序是一条真实的流水线，尺寸校验本质就是"检测"。用"检测仪器"做视觉隐喻，比任何通用后台模板都贴题。

## 3. 三根支柱

### 3.1 色彩：一种主张力 + 两个信号

**深色（默认）**

| 角色 | 令牌 | 值 | 用途 |
|---|---|---|---|
| 页面底 | `--bg-0` | `#070a0b` | 最底层的墨，冷调近黑 |
| 面板 | `--bg-1` `--bg-2` | `#0b1113` `#0f1618` | 主舞台 / 抬升面 |
| 顶栏·表头 | `--bg-3` | `#141d20` | 结构层 |
| **主张力 · 磷光青绿** | `--accent` | `#2fe3c0` | 选中、焦点、计数格、轨道的"活"节点 |
| 张力深调 | `--accent-deep` `--accent-glow` | `#0e3b35` / `rgba(47,227,192,.28)` | 底纹 / 辉光 |
| **信号 · 琥珀** | `--amber` | `#f4a63c` | 生产中 / 载入中（设备运行灯） |
| **信号 · 红宝石** | `--ruby` | `#ff5d4f` | 尺寸不匹配 / 未找到 |
| 通过 | `--good` | `#33d69f` | 判定匹配 |
| 文字 | `--text` `--text-dim` `--text-faint` | `#e8f3f0` `#8fa3a0` `#5a6a68` | 三级信息层级 |

**浅色（昼间模式）**：不是简单反色，而是"白天把灯打开"。
底 `#e6ebec`（冷纸灰，不是纯白）、面板 `#ffffff`、青绿压深到 `#0a8f77`（保证白底对比度）、红宝石 `#cf3a2c`。

> 关键纪律：**一个界面里同屏只出现一种张力色（青绿）**，琥珀与红只在"有状态"的地方点亮。层级由**底色深浅 + 线条 + 辉光**拉开，而不是靠更多颜色。

### 3.2 字体：三分工，各有性格

| 角色 | 字体 | 为什么 |
|---|---|---|
| 显示 / 标签 / 表头 | **Chakra Petch** | 方正、带切角的技术感，天生"仪表盘"，用于 wordmark、大写小标题、表头、按钮 |
| 数据 / 编码 / 数字 | **IBM Plex Mono** | 等宽、有工程气质，承载所有 JIG ID / P/N / 计数，配 `tabular-nums` 纵向可扫读 |
| 中文正文 | **Noto Sans SC** | 高可读性的中文字体，400/500/700/900 全字重，900 用于空态大字 |
| （空态大字） | Noto Sans SC 900 + 渐变裁切 | 用"金属渐变文字"做一个视觉锤 |

> 与现状的关键差异：现在正文与数字共用一种字体、只在数字上开 `tabular-nums`。
> 新方案把**数据升格为一套独立字体系统**——编码读起来像仪器读数，而不是表格文本。

### 3.3 形态：线条 + 辉光 + 颗粒

- **发丝网格背景**：整页铺 28px 网格线（透明度极低）+ 两处径向辉光，让"纸"变成"屏"。
- **胶片颗粒层**：SVG `feTurbulence` 噪点，`mix-blend-mode: overlay`，透明度 5%。深色不再"塑料"。
- **圆角克制**：7px 主圆角、4px 小圆角，硬朗但不生硬。
- **发光纪律**：辉光只给"活的东西"——选中标签、主力工序节点、计数格、焦点环。静态结构一律不发光。

## 4. 组件级改造清单

### 4.1 顶栏 → 控制台条
- 左侧方形 logo（青绿径向渐变 + 自发光），wordmark 用 Chakra Petch 拉字距。
- 文件名做成**琥珀/绿灯状态胶囊**（带一颗发光 LED = 数据已装载）。
- 右侧按钮：主操作用青绿渐变实心 + 外发光；图标按钮收成方形。
- 顶栏底部加一条**贯穿的青绿渐隐光线**，把"仪器通电"的感觉点出来。

### 4.2 侧栏 → 输入舱（Input Bay）
- `输入 JIG ID` 改成仪表标签式 eyebrow（大写 + 拉字距 + 英文小字）。
- 文本框套一个**暗色凹槽**：四角有青绿描边角标、内部 `inset` 辉光、叠加扫描线纹理。
- `开始查询` 升级为**致动按钮（Actuator）**：大写、拉字距、实心青绿、按压位移 1px。

### 4.3 标签栏 → 通道选择器
- 选中态：文字加粗 + 底部 2px 青绿光条（`scaleX` 弹出 + 外发光）。
- 计数徽章：选中时变成青绿描边 + 深绿底。
- 右侧工具区：`标出尺寸不匹配` 从原生 checkbox 升级为**拨动开关**（17px 滑块 + 发光轨道）。

### 4.4 工序轨道 → 产线流（★ 签名元素）
这是整套方案里最"值得被记住"的一处：
- 11 道工序排成一条水平流线，节点之间一条**极细的连接线**贯穿。
- 节点状态三档：
  - **lead（主力）**：青绿实心点 + 呼吸脉冲 + 计数青色发光；
  - **on（有数）**：青绿点 + 白色计数；
  - **off（0 值）**：灰点 + 灰计数 —— 一眼看出"今天还没有 JIG 走到搬出"。
- 流线上有一道**流动的光带**（`@keyframes flow`）缓慢掠过，暗示"产线在动"。
- 每个节点下方一条**归一化细条**，长度 = 该工序计数 / 峰值，主力工序自然成为视觉锚点。
- 数字进场时**从 0 滚上去**，让"数据刚刚刷新"这件事被感知到。

### 4.5 数据网格 → 仪器读数表
- 表头：Chakra Petch 大写小字 + 拉字距、顶部那层微渐变，像仪表面板刻字。
- 数据单元格：编码/ID 用 IBM Plex Mono；纯数字列右对齐 + `tabular-nums`。
- 行悬停：一层极淡的"扫过"底色（`--shot`）。
- **P/N 小计行**：P/N 用青绿、整行底纹抬升、加粗 —— 小计不靠颜色乱标。
- **总计行**：`position: sticky; bottom: 0` 钉在可视区底部 + 顶边线，像仪器的"合计读数"。
- **计数格（可下钻）**：青绿数字 + 悬停时冒出 `›` 箭头，暗示"可点进去"。主力计数格额外带青色文字发光。

### 4.6 异常表达 → 信号灯不靠红字
- **未找到行（查询结果）**：整行淡红底 + P/N 位显示 `—` + `未找到` 红色胶囊徽章。
- **尺寸不匹配行（数据审查）**：左侧 2px 红宝石灯条 + **呼吸脉冲动画**，尺寸码那格单独红字；判定列用红色胶囊徽章。即使黑白打印/色弱，也靠"左灯条 + 位置"能定位。

### 4.7 面板与对话框 → 玻璃仪器
沿用项目既有的对话框骨架，但换装：
- 背板：深底 + 1px 结构线 + 内辉光；顶部一条细的青绿状态线。
- 焦点环：青绿 `--accent-glow`，明确"当前在哪台仪器上"。
- 保留项目铁律「点遮罩空白不关闭」（这是用户明确要求过的行为）。

### 4.8 状态栏 → 仪表读数
- 三组等宽读数：`● 已装载 205 行 · 9 列` / `查询 5 条 · 命中 4 · 未找到 1` / `源 205 行 · 当前 13 行`。
- 前面挂一颗**绿色发光 LED**，把"系统在线"做成一个持续存在的信号。

## 5. 动效编排

动效只服务两件事：**"数据在动"的感知** 和 **焦点引导**。不做无意义的装饰。

| 时机 | 动效 | 时长/曲线 |
|---|---|---|
| 页面进场 | 工序轨道节点计数**从 0 滚到目标值**，逐节点错峰 45ms | 900ms，`easeOutCubic` |
| 切换标签页 | 内容区**淡入 + 上移 8px** | 340ms，`cubic-bezier(.4,0,.2,1)` |
| 标签选中 | 底部光条 `scaleX(0→1)` 弹出 | 220ms，同曲线 |
| 产线流 | 光带在流线上**缓慢掠过** | 5.5s，linear，无限 |
| 主力工序节点 | 点**呼吸脉冲**（辉光扩散） | 1.9s，ease-in-out，无限 |
| 异常行灯条 | **呼吸脉冲** | 2.2s，无限，仅改透明度 |
| 计数格悬停 | 冒出 `›` 箭头 | 140ms |
| Toast | 从下方 20px **滑入 + 淡入** | 300ms |

> 动效总量刻意克制：**同一时刻最多两处持续动画**（产线流光 + 一处呼吸），其余都是瞬时反馈。避免"到处都是动的东西"变成噪音。

## 6. 记忆点（What makes it UNFORGETTABLE）

1. **产线流**：11 道工序以发光轨道呈现，0 值节点自然沉入暗处 —— 这是全行业都少见、只属于 JIG 现场的一种可视化。
2. **暗场中的磷光**：整个界面只有一种"有颜色"的活物（青绿），其余全是冷灰结构，异常才用红点破。
3. **数据即读数**：所有编码换成等宽仪器字体，纵向扫描时像在看一排仪表。
4. **金属渐变大字**：空态用 900 字重 + 青绿金属渐变裁切，冷硬但高级。

## 7. 落地映射（概念 → 代码落点）

因为高保真稿是**独立 HTML**（不依赖项目现状），实际迁移时可按这张表对应：

| 概念 | 落地文件 | 做法 |
|---|---|---|
| 色彩令牌 | `src/styles/tokens.css` | 替换 `:root` 与 `[data-theme='dark']` 的值；`--accent` 系列、`--signal`→红宝石、新增 `--amber` 语义位 |
| 网格底 + 颗粒 + 辉光 | 新建 `src/styles/atmosphere.css` | `body` 背景多层 `linear-gradient` + 一个 `.grain` 固定层 |
| 字体三分工 | `index.html` 的字体 link + `tokens.css` 的 `--font-*` | 引入 Chakra Petch / IBM Plex Mono / Noto Sans SC |
| 产线流 | `src/ui/StageRail.tsx` + 对应 CSS | 结构基本不变，改 `.stage*` 的样式与 `.rail__flow` 的流动层 |
| 仪器读数表 | `src/ui/Grid.tsx` 的 class + `app.css` | 只改样式（表头字体、sticky 总计、计数格、异常灯条），**Grid 的 CSS Grid 机制与虚拟滚动不动** |
| 拨动开关 | `src/App.tsx` 的开关节点 + `app.css` | 沿用现有 switch 结构，重画轨道与滑块 |
| 标签光条 | 已引入的 shadcn Tabs + `app.css` | 保留 `aria-selected` 选择器（现有代码已在用），只加 `::after` 光条 |
| 入驻动效 | 新建 `src/ui/useCountUp.ts` | 一个极小的 hook，工序节点与总计行复用 |

> 迁移原则沿用项目既有做法：**保留 class 名，只换令牌与样式**——diff 小、可回滚、不碰 `src/core/*.ts`。

## 8. 分期实施路径

| 阶段 | 内容 | 风险 |
|---|---|---|
| **P0 令牌换血** | 只改 `tokens.css` 的值 + 引入字体 + 加网格/颗粒背景 | 极低，可一键回滚 |
| **P1 结构深化** | 顶栏/侧栏/标签栏/状态栏的形态升级（发光、角标、开关、光条） | 低 |
| **P2 签名元素** | 产线流重做 + 入场数字滚动 | 中（需实机确认性能） |
| **P3 表格与异常** | 表头字体、sticky 总计、计数格、异常灯条 | 低（纯样式） |
| **P4 面板收尾** | 设置/型号尺寸匹配两个对话框换装 | 低 |

每一阶段后跑 `npm run verify` 即可；P2 之后建议按项目铁律**先申请再做实机验证**。

## 9. 关于"忽略约束"的说明

这份方案**有意突破了项目现有的两条硬约束**（用户已明确授权）：

1. **网络字体**——原项目坚持"离线只用系统字体"。方案引入了三款网络字体；若要保留离线，可用 `Chakra Petch`→`Bahnschrift`、`IBM Plex Mono`→`Cascadia Mono`、`Noto Sans SC`→`微软雅黑` 做降级替身，观感损失约三成但仍远胜现状。
2. **单一彩色**——原项目规定"表格里只允许一种彩色（不匹配红）"。方案引入了青绿 + 琥珀 + 红宝石三色，但通过**严格的用法纪律**保持克制：青绿是唯一的"活色"，琥珀与红只在状态处点亮，结构与文字仍是无彩色。

若未来要在真实项目里落地，这两条可以按现场偏好再收紧。
